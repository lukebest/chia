## 7. CHIA 五个案例：证据与证据之外

把前文的记账模型与边界条件放回真实系统里检验，开源软硬件协同设计框架 CHIA [1] 的五个案例恰好提供了一组正反兼备的切片。这些案例分别落在架构探索、模拟器对齐、RTL 扩展、物理时序收敛与编译器修复五个位置——它们有的直接支撑了本文的某个环，有的则暴露了还没补上的缺口（见表 C）。

| 案例 | 它支持什么 | 它没有检验 / 挑战什么 | 一个关键事实 |
|---|---|---|---|
| **架构发现**（`architectural-discovery-basic`） | 探索候选本身就是可执行代码（C++ 预取器结构体），fitness 由模拟器自动给出；评估器三函数接口（`build_fn` / `run_fn` / `result_mapper_fn`）支持直接替换底层模拟器 | ChampSim 是 trace 驱动模拟器，产出**不是 RTL-ready 的周期模型**（据 CHIA 论文，其亦无法提供功耗、面积与关键路径反馈）；无 RTL 落地 | LLM 提出 C++ 候选 $\to$ 编译 $\to$ 并行跑 trace $\to$ geomean IPC；构建失败得 0.0 且搜索继续；简化版跑 3 条 SPEC CPU 2017 trace、5 个 worker、10 次迭代，1 小时内完成 [1]（沿用 ArchAgent [2] 范式） |
| **gem5 对齐**（`gem5_align`） | Agent 有能力修改 C++ 与配置产出与 RTL 对齐的周期级模型；按 PC 对齐的 O3PipeView 流水线 trace 与 BOOM TMA 计数器对照，构成 $M \leftrightarrow R$ 性能对齐工具链的现成蓝本 | 直接挑战对齐成本假设；方向是“模型追 RTL”的逆向工程，**没有检验“RTL 追模型”**，且存在针对训练基准的过拟合 | 在 2-wide MediumBOOM 上运行 10.5 天（据 CHIA 论文为 202 次迭代、API 成本 \$2,355.98、1,520 行 diff），训练集 36 个微基准平均周期误差 $<3\%$，但留出集 Embench IOT 2.0 最佳迭代平均误差为 $<7\%$ 且有离群点（据 CHIA 论文）[1] |
| **RISC-V 扩展**（`riscv_extensions`） | **可执行规约作 oracle 与付费者转移的最强证据**：Spike 编译进仿真器做逐指令 lockstep，无手写期望输出；分歧在发生的周期被捕获并作为 $m_t^o$ 驱动 debug LLM 修复 RTL；directed test 由指令表生成，指令覆盖率按构造为 $100\%$ | 只是 **ISA 级功能 oracle**，不是周期级性能 oracle；实现的是已批准的 ISA 扩展（先验覆盖高），并未涉及新微架构机制探索 | MegaBOOM 上实现并验证 Bitmanip、标量密码与 Zicond（据 CHIA 论文分别仅需 2 / 6 / 1 次 LLM 迭代，cosim 占机时 $50\%\text{–}66\%$，FireSim 跑通 25+ 万亿条指令），取得约 $5.6\%$ 与 $3.5\%$ 几何平均加速、OpenSSL 最高 $10\times$，无时序回退 [1] |
| **时序优化**（`timing-optimization`） | IPC-neutral 提示词表明“固定周期行为 $M$、只在精化集合 $\mathrm{Refine}(M)$ 内优化物理质量”是独立可解的子问题；`timing_experiment` 子模块 A/B 综合支持低成本局部验证 | 挑战单向解耦：Iron Law 耦合使 IPC-neutral 平台化之后的进一步收益必须改变周期行为 $M$；开放工艺上的物理改进未必能跨工艺泛化 | 15 次迭代将频率提升 $>2\times$（据 CHIA 论文为约 47 MHz $\to$ 95 MHz，即 $2.03\times$）、IPC 仅损失 $3.3\%$、净 Iron-Law 性能提升 $1.97\times$（Sky130）；据 CHIA 论文，前 4 次 IPC-neutral 迭代后陷入平台化才切换模式，且在商用 16nm 下仅第一项优化泛化 [1] |
| **CIRCT issue**（`circt-issue-solving`） | **歧义显式化**：`assess` 阶段枚举实质不同的合理解法，数量 $>1$ 且无依据时返回 `UNCLEAR`，拒绝盲目打补丁；`repro.sh`（“exit 0 iff fixed”）充当可执行修复规约，`verify` 阶段无 LLM 参与 | 属于编译器修复任务，与周期模型及硬件微架构无直接对应关系，仅提供方法论上的同构证据 | 评估 16 个 issue，5 个可复现且方案明确的全部解决，3 个 PR 被上游接受（据 CHIA 论文，另有 4 个因存在多种合理解法被判为 Fix unclear）[1] |

*表 C：CHIA 五个案例与本文论点的证据映射。*

把这五个切片连起来看，有三条线索最值得拎出来。

第一，`riscv_extensions` 把第 3.5 节信息论里的“迭代修正”做成了一条全自动通道。在这个流程里，人写下的只有扩展规约与结构化的指令表，真正驱动 RTL 收敛的修正消息全部来自 Spike 逐指令比对吐出的第一处分歧 trace——据 CHIA 论文，修复代码的 LLM 甚至对底层验证基础设施一无所知，它只接收必要的分歧片段 [1]。更耐人寻味的是文档里的一句原话：**“the flow verifies a BOOM implementation, it doesn't invent the ISA”**（该流程验证的是 BOOM 的实现，它并不发明 ISA）[1]。换句话说，**“发明规约（探索）”与“忠实实现（精化）”在这个案例里本来就是拆开的**。这正是本文主张在 ISA 层的现成样板；它留给我们的未竟之业，就是把这套机制从 ISA 级功能 oracle 往下推一层，变成周期级性能 oracle。

第二，CIRCT 案例的 `UNCLEAR` 门与本文的周期模型遵循同一个底层逻辑。据 CHIA 论文，早期原型中评估器与修复器曾对 issue #8508 的“正确修法”各执一词，团队随后才立下规矩：只要存在不止一种合理修法且缺少决断依据，就必须停下来报 `UNCLEAR` [1]。这说明：**当没有可执行规约时，工程底线是把沉默的歧义显式化；而当有了周期模型 $M$ 与合法差异规则 $\Delta$ 时，我们做的正是同一件事——用 $(M, \Delta)$ 把哪些行为必须对齐、哪些周期差异允许放行一条条写成代码与规则，不给 agent 留下悄悄猜题的空间。**

第三，我绝不会把这五个案例写成“都支持我的论点”。恰恰相反，CHIA 的五个案例只提供了若干关键拼图的证据，却没有检验完整的桥：架构发现案例的 ChampSim 产出停留在 trace 驱动层，离 RTL-ready 周期模型还有一道鸿沟；而 `gem5_align` 与时序优化则是对本文假设挑战最大的两个案例——前者暴露了周期级对齐的高昂成本与过拟合风险，后者揭示了脱离物理反馈的单向探索会在 Iron Law 面前撞墙。正是这两个案例，逼出了前文关于“多保真度级联”“方向翻转”与“双向外环 + PPA 代理”的全部收窄。

## 8. 可证伪的预测与下一步

一个有价值的工程框架，不能只解释已经发生的事，还必须敢于给出可被实验推翻的预测。围绕前文的核心论点与收窄后的假说，我给出四条可证伪的预测：

- **P1（对齐媒介对比）**：针对同一个新颖微架构特性（如探索产出的新型预取或发射仲裁机制），在 CHIA 中搭建类似 `riscv_extensions` 的闭环做 A/B 对照实验，比较向 RTL agent 提供“周期模型 $M$ + 协同仿真 oracle”与提供“等价意图的详尽自然语言规约 + 常规测试”。**可观测量**为达到功能正确且周期级性能误差 $\le$ 给定阈值所需的人类干预次数与总 token/算力成本。我预测周期模型路线的人类干预次数将显著更低；**若两条路线在人类干预成本上无显著差异，则第 3 节关于“可执行代码将沉默歧义转化为机器可检测分歧并转移付费者”的强版本论点被否证。**
- **P2（对齐方向性对比）**：针对同一对微架构与周期模型（例如 MediumBOOM 与其对应的周期模型），在相同基准测试集与算力预算下，比较“RTL 追模型”（以给定的 $M$ 为规约指导 agent 精化或修改 RTL）与 `gem5_align` 的“模型追 RTL”（以写死的 RTL 为目标逆向修改模型）两个方向。**可观测量**为达到相同训练集周期误差（如 $<3\%$）所需的迭代次数，以及在留出集（如 Embench）上的泛化误差差距。我预测“RTL 追模型”所需的迭代次数与留出集退化幅度均小于“模型追 RTL”；**若反之，则第 5.1 节关于“规约误差主导导致逆向工程更贵”的方向性假说被否证。**
- **P3（多保真度可实现性对比）**：比较直接在 trace 驱动模拟器（如 ChampSim）上探索出的 top-$k$ 候选设计，与经由“周期模型 $M$ + 排序正确的 PPA 代理”级联筛选出的 top-$k$ 候选设计，将两组入围方案统一交由下游 RTL 精化与综合流程（如 Chipyard + Hammer）落地。**可观测量**为两组候选在给定 PPA（目标频率与面积）预算下成功收敛并保住性能增益的存活比例。我预测前者的存活率将显著低于后者；**若两者存活率相当，则第 2 节与第 5.2 节关于“探索交付物须升级为周期模型并配合 PPA 代理”的收窄论点被否证。**
- **P4（社区基准演化，注：这是一条较弱的趋势判断）**：观察未来一至两年内社区新建或迭代的 RTL agent 评测基准（如 CVDP [7]、ChipBench [6] 的后续版本）。**可观测量**为新基准是否普遍增设“以可执行参考模型作为输入”的赛道，以及同一批前沿模型在该赛道上的 pass@$k$ 通过率相对纯自然语言赛道的增幅。**若主流基准仍停留在纯自然语言规约且两类输入下模型通过率拉不开差距，则本文关于“复杂硬件对齐媒介向可执行代码迁移”的趋势判断被否证。**

落回当下，要在 CHIA [1] 现有的代码底座上把这座桥真正搭起来，下一步有四件具体可做的事：
1. **替换探索尾声的评估器**：利用 `architectural-discovery-basic` 已经抽象好的 `build_fn` / `run_fn` / `result_mapper_fn` 三函数接口，在外层 ChampSim 广搜之后，接入周期级模型作为入围候选的升级评估与交付通道。
2. **把 `gem5_align` 的工具链倒过来接进 RTL 回路**：复用 `gem5_align` 中按 PC 对齐的 O3PipeView 流水线 trace 比对与 TMA 性能计数器对照工具，将其改造为 RTL 精化阶段检验 $R \models M$ 的自动化诊断反馈生成器。
3. **定义周期模型的受限接口与显式 $\Delta$ 规范**：在周期模型中强制声明存储容量、端口数与每周期逻辑预算（堵住 ArchAgent [2] 式的 simulator escape），并设计一套轻量级的合法周期差异声明语法 $\Delta$。
4. **跨工艺校准频率代理并量化 $\varepsilon$**：基于时序优化案例的数据，在 Sky130 与另一工艺节点上对候选微架构改动做成对综合，拟合频率代理 $\hat f$ 并实测第 5.2 节代理引理中的最大相对误差 $\varepsilon$。

如果要把整篇文章压缩成三句话带走，那就是：

> - **架构探索真正有价值的产出，恰恰落在模型先验覆盖不到的盲区；那正是自然语言对齐必然亏本的区间——所以它只能以可执行代码交付。**
> - **多轮迭代对齐的总信息量是守恒的；可执行模型改变的不是信息总量，而是谁来买单：把人类手写的修正描述，换成机器在协同仿真中抓出的第一处分歧。**
> - **让模型去追 RTL 是逆向工程，误差主要来自“猜不准硬件到底怎么做”；让 RTL 去追模型是精化检查——这在 ISA 层早已是工业标准，现在该把它推到周期层了。**

回到开篇的那个问题：当 AI agent 让“写代码”本身变得越来越便宜，硬件研发真正的瓶颈就不再是把代码敲出来的速度，而是如何以最低的歧义成本把“要做什么”交代清楚并验证通过。与其写完 RTL 再花十几天去逆向校准一个迟到的模拟器，不如从一开始就把方向倒过来——让架构探索交付一段可执行的周期模型，再让 RTL 对模型精确。
